# 更新后告诉用户「这版多了什么」（What's New）· 设计

日期：2026-10-16　状态：loki 已同意方向和卡片样式（10-16），待 loki 审阅本文

## 为什么做

很多人不看 GitHub 的发布说明，更新完只听到她说一句「更新好啦～现在是 v1.3.5」，不知道多了什么新玩法（比如 1.3.6 的 Codex 重置提醒默认关着，不知道就永远不会打开）。

## 目标

- 更新后第一次打开：她头顶弹一张精简卡片「更新好啦～这次多了 N 个新功能」，下面两个按钮：点「去看看」打开设置里的「新功能」页，点「知道了」收起
- 设置里新增第六个标签「新功能」，随时能看最近几版的新功能，每条能跳到对应的开关
- 只讲**新功能**，不讲修了什么（loki 定）
- 文案是**专门写给普通用户的短文案**，不是 CHANGELOG 原文（loki 定）
- 两端（macOS / Windows）一致；判断写在网页层（`docs/架构.md`）

不做：修复说明、配图 / 动图、每条单独的「已读」、在应用里联网拉取发布说明（文案随包发布）。
反面目标：不能变成弹窗打扰——一次更新只弹一次，不点也会自己收起；她在演彩蛋、AI 在干活时不弹。

## 一、更新后的卡片（loki 选 B「弹卡片」，样式选 C「精简卡片」）

- 时机：外壳检测到「这次打开的版本比上次新」（现有 `lastVersion` 逻辑）时调网页 `justUpdated(新版本, 上次版本)`（**加第二个参数**）。新安装（没有上次版本）不弹
- 内容（loki 选 C）：**只有一句话 + 两个按钮**，不列具体功能——「更新好啦～这次多了 N 个新功能」，下面「去看看 ›」「知道了」。N = 所有「比上次版本新、且不比当前版本新」的版本里的新功能条数（跳过版本的人会合在一起算）。一条都没有（纯修 bug 的版本）就不弹卡片，只说原来那句「更新好啦～现在是 v…」
- 位置和大小：放在**气泡的位置（她头顶）**，用气泡的样式（边框色 `--accent`、字号随 `--k` 缩放），高度不超过现在留给气泡的那块（基础画布人物上方 59 × `--k`，见 `text-size.js` 的 `BASE`，气泡本来就往下压住头顶 10 × `--k`）。**窗口大小不变**，不改 `text-size.js` 和两端调窗口的代码。卡片出现时气泡收起，卡片收起后她才说别的
- 收起：点「知道了」、点「去看看」、30 秒没点、开始演彩蛋，都收起。卡片只出现这一次（重启不再出现）
- 换角色（我的判断）：卡片属于整个桌宠，不属于某个角色——**换角色（包括「跟随前台应用」自动换）不收起卡片**，换完照样留着（边框色跟着新角色）
- 不打扰：彩蛋中、AI 在干活（`aiActivity() === 'work'`）、正在道别 / 更新中时先不弹，等她闲下来（每 20 秒看一次，最多等 10 分钟，等不到就算了——设置里的小红点还在）

## 二、设置里的「新功能」页（loki 选 A）

- 标签：第六个「新功能」，排在「通用」后面。`data-tab="news"`
- 小红点：存在「比 `whatsNewSeen` 新、且不比当前版本新」的版本条目时，标签旁一个小红点（跳版本落到纯修 bug 的版本时，跳过的那些版本的条目也算）；打开这一页就记为看过（存外壳设置 `whatsNewSeen` = 当前版本），红点消失
- 新安装（我的判断）：第一次启动时外壳把 `whatsNewSeen` 设成当前版本，不亮红点（和不弹卡片一致）；升级上来的老用户没有 `whatsNewSeen` 时，按 `lastVersion` 当作看过的版本
- 内容：最近 **5 个有新功能的版本**（我的判断），最新一版展开在最上面，标注「当前版本」；更早的折叠，每行「版本号 · 第一条的标题」，点开看全部。再早的去 GitHub 发布页（页底一个链接「更早的更新记录 ›」，用外部浏览器打开 `https://github.com/lokicorvus/crosspet/releases`）
- 每条：小图标（emoji）、标题、一两句怎么用；和某个开关有关的，右边「去设置 ›」：切到那个开关所在的标签页、滚到那一项、闪一下高亮（比如重置提醒 → 额度页的 `codexResets` 那一项）
- 从卡片的「去看看」打开设置时，直接停在这一页（不是上次停的标签）

## 三、文案从哪来

- 新文件 `app/web/whats-new.js`（两端共用，随包发布），每版发版前手写。格式（示例，即 1.3.6 的内容）：

```js
[
  { version: '1.3.6', items: [
    { icon: '🔔', title: 'Codex 重置提醒', text: '官方提前宣布重置时，GPT 的额度下方会多一行；右键「会重置吗？」可以问她。默认关，在「设置 → 额度」打开。', go: { tab: 'quota', key: 'codexResets' } },
    { icon: '🐉', title: 'GPT 的新动作', text: '查手机、摇铃铛、期待、怀疑、摇头，原版和降智龙崽各一套。' },
  ] },
  { version: '1.3.5', items: [ ... ] },
]
```

- 第一次上线时补好 1.3.6、1.3.5、1.3.4 三版的文案（由 Claude 起草，loki 过目）
- 发版流程加一步：写 `whats-new.js` 的新版本条目（没有新功能的版本不写）
- 纯函数（同一文件或 `whats-new-logic.js`，node 测试）：`since(list, last, current)`（比 last 新、不比 current 新的条目，卡片用它数 N）、`unseen(list, seen, current)`（要不要亮红点，同样的范围）、`recent(list, n)`
- 测试版（我的判断）：比较前去掉版本号的 `-test.N` 这类后缀，按正式版本算——`1.3.6-test.2` 看到的就是 1.3.6 的条目；从 `1.3.6-test.1` 升到 `-test.2`、或从 `1.3.6-test.N` 升到 `1.3.6`，去掉后缀后版本相同，**不弹卡片**（测试时要看卡片，把 `lastVersion` 改成旧版本再开）

## 四、点击（实现上要新加的）

现在两端外壳把对桌宠的单击一律当「摸头」（Windows `hit.MouseLeftButtonUp → handleClick('pat')`，macOS `DragView.mouseUp → onClick`），网页不知道点在哪。卡片上的按钮需要知道位置：

- 外壳在单击（没拖动）时把位置一起交给网页：`handleClick('pat', x, y)`，x、y 是**网页坐标**（CSS 像素，已经除掉人物大小的缩放；macOS 注意 y 轴翻转）
- 网页先看这个点是不是落在卡片的按钮上（`document.elementFromPoint` 找带 `data-action` 的元素），是就执行按钮，不摸头；落在卡片别处什么都不做；不在卡片上才照常摸头
- 卡片要算进可点区域（`hitRects()` 加上卡片），不然 Windows 上点卡片会穿透到后面的窗口
- 「去看看」：网页通知外壳打开设置并停在「新功能」页。Windows 用已有的 `chrome.webview.postMessage`（现在只用来报立绘加载失败）加一种消息；macOS 桌宠页面现在**没有**消息通道，要像设置页那样加一个（`userContentController.add(..., name: "pet")`）
- 外壳打开设置后调设置页的 `showTab('news')`；设置窗口已经开着时也要切过去

## 五、测试

- `tests/whats_new.test.js`：`since`（跳版本合计、纯修 bug 版本返回空、带 `-test.N` 后缀按正式版算、同一正式版的测试版之间返回空、上次版本比当前还新时返回空）、`unseen`（含跳到纯修 bug 版本、新安装）、`recent`
- 浏览器：卡片的样子和缩放（人物 60% / 160%、文字解锁时不超出头顶那块、不被窗口裁掉）、30 秒收起、换角色不收起、彩蛋 / 干活时不弹；`handleClick` 带坐标时点按钮 / 点卡片空白 / 点人物；设置页红点、展开折叠、「去设置 ›」跳转高亮
- 两端：编译；Mac 实测（改 `lastVersion` 为旧版本后重开看卡片，点「去看看」）；Windows 由 Codex 跑一轮，重点是点击坐标换算（系统缩放 100% / 150%、人物大小不是 100% 时点得准）
