# 文字大小和人物大小分开调 · 设计

日期：2026-10-13　状态：loki 已同意（10-13）；写计划时修订两处（见「修订」）

## 为什么做

用户反馈：桌宠默认有点大，调小以后名牌、气泡、额度的字也跟着变小，看不清。现在整张网页按「大小」一起缩放，人调到 60% 时气泡字只剩约 8px、额度字约 6px。

## 目标

- 人物可以调小，字保持看得清；字和人可以分开调
- 默认和现在完全一样（老用户升级后看不出变化）
- 拖动、贴边、点击穿透照常；调大小时人物在屏幕上不动
- 判断写在网页层，外壳只照办（`docs/架构.md`）

不做：字跟着内容自动伸缩、各部分（气泡 / 额度）分别调字号。

## 一、设置和数据

**界面**（设置 → 外观）：

```
人物大小  [━━━━●━━━]  100%  还原
            🔗
文字大小  [━━━━●━━━]  100%
```

- 像 PS 改图像大小的锁链：**锁着**（默认）时拖人物，文字滑块跟着动，文字 = 人物
- 拖文字滑块：自动**解锁**，图标变断开，之后各调各的
- 点锁图标：重新锁上，文字回到 = 人物
- 「还原」：人物、文字都回 100%，并锁上
- 文字范围和人物一样：60%～160%

**存储**（两端设置里新增，原来的 `size` 不变）：

| 键 | 类型 | 默认 | 含义 |
|---|---|---|---|
| `size` | 数字 | 1 | 人物大小（原有） |
| `textSize` | 数字 | 1 | 文字大小，只在解锁时用 |
| `textLinked` | 布尔 | true | 是否锁着 |

实际文字大小 `text = textLinked ? size : textSize`。设置页的 `set` 消息：拖文字发 `textSize`（外壳同时记为解锁）；锁着时点锁发 `textSize = 当前人物大小`（解锁、字不变）；解开时点锁发 `textLinked=true`；「还原」发 `size=1`、`textLinked=true`。

**跟着谁走**：

| 跟文字 | 跟人物 |
|---|---|
| 说话气泡 `#bubble`、名牌 `#caption`、额度小窗 `#quota`（含合并表格、tight 模式） | 立绘、特效、工具卡片、「+N」角标、光晕、影子 |

## 二、窗口尺寸

**网页里怎么缩放文字**：整张网页仍按人物大小缩放（外壳的 `pageZoom` / `ZoomFactor` 不变）。气泡、名牌、额度的尺寸（字号、内边距、最大宽度、圆角……）都写成 `calc(原来的像素 * var(--k))`，`k = text ÷ size`，屏幕上的字就正好是「文字大小」。底栏最小高度是 `62px × max(1, k)`：字变小时底栏不缩，人物不往下掉。锁着时 `k = 1`，和现在一样。

**画布尺寸（网页层算，只此一份；放在新文件 `app/web/text-size.js`，和 `codex-quota.js` 一样能单独测）**，基准 260×362：

- `k ≤ 1`：260×362，不变
- `k > 1`：
  - 宽 `W = max(260, ceil(240k + 20))`（气泡最宽 228、额度最宽 236，两边留空）
  - 高 `H = 362 + ceil(121(k − 1))`（人物上方 59 给气泡、下方 62 给底栏，都按 k 放大）
  - 底栏高 `F = 62·max(1, k)`
- 例：人物 60%、文字 100%，k≈1.67 → 画布 420×443 → 屏幕窗口 252×266（比现在 100% 时还小）
- 只看两个设置值，不看当前内容：气泡出现 / 消失时窗口不变

**网页 ↔ 外壳**：

1. 外壳调网页 `setSizes(size, text)`（启动、设置变化时）
2. 网页设好 `k`，算出 `{w, h, foot}`，通过消息通道发 `{ pageSize: {w, h, foot} }`
3. 外壳：窗口 = `w·size × h·size`，缩放 = `size`；水平按中心对齐；垂直：底栏高（网页像素）没变时窗口底边不动（和现在改大小一样），底栏变高 / 变矮多少（× size），窗口底边就往下 / 往上挪多少，人物不动
4. 启动时先按 260×362×size 开窗口，网页加载后再调一次（锁着的用户尺寸不变）
5. 拖人物滑块的平滑动画（`animateScale` / `AnimateScale`）照旧，每一帧用当前画布尺寸

**外壳里按「窗口宽 ÷ 260 = 缩放」算的地方，全改成用真实缩放值（人物大小）**：

| 用途 | macOS | Windows |
|---|---|---|
| 点击穿透：鼠标 → 网页坐标 | `App+ClickThrough.swift` `zoom = f.width / baseSize.width` | `Pet.Mouse.cs` `zoom = Window.Width / BaseWidth` |
| 贴边：切口 → 屏幕坐标 | `App+Dock.swift` `tuck` 里的 `zoom` | `Pet.Dock.cs` `zoom = w / BaseWidth` |
| 贴边：离屏幕边多近算「拖到边上」 | `checkDock` `reach = f.width * 0.3` → 用人物宽 260·size | `Pet.Dock.cs` `reach = w * 0.3` 同改 |
| 平滑动画的起点 | — | `Pet.Settings.cs` `from = Window.Width / BaseWidth` → 用 `shownScale` / `Scale` |

- 贴边切口量的是元素实际位置（网页坐标），画布变宽、人物居中后自然正确；记下的切口（`dockCut`）在画布尺寸变化时清空
- 贴边时气泡、名牌、额度本来就隐藏，不受文字大小影响

## 三、风险

- ~~CSS `zoom` 下 `getBoundingClientRect` 两个内核不一致~~：已改成 `calc(… * var(--k))`，元素位置就是普通布局结果，点击穿透和贴边切口不受影响
- **窗口变大后挨着屏幕边**：人物不动、窗口往下扩，底边可能超出屏幕可见区。只在超出时整体往上挪回可见区（和现在拖到边上的处理一致）

## 四、测试

- **网页层单元测试**（`tests/text_size.test.js`，node）：画布公式——`k=1` 不变、`k<1` 不变、`k=1.67` 的宽高底栏、只依赖两个设置值；锁定逻辑——锁着时 `text=size`，拖文字解锁，点锁回到 `=size`，「还原」全回 100% 并锁上
- **浏览器验证**：桌宠页注入 `setSizes(0.6, 1)`，截图看气泡、名牌、额度、合并表格（含 tight）大小和位置；`hitRects()` 返回的矩形对得上元素；设置页的锁图标交互
- **Mac 实机**：人物 60% / 文字 100%：拖动、点击穿透（透明处点得穿、字上点得到）、贴边左右缩进去 / 探出来、调滑块时人物不动
- **Windows**：写测试方案交给 Codex 跑，同上几项 + 隐身 / 恢复后尺寸不变
- 锁着（默认）的用户：两端窗口尺寸、位置和升级前完全一样（回归）

## 修订（写计划时，10-13）

1. 放大方式从 CSS `zoom` 改成 `calc(原像素 * var(--k))`：两个浏览器内核里元素位置算法一致，去掉风险
2. 「人物不动」细化：改人物大小时和现在一样底边不动；只有底栏高度变了（改文字大小）才按差值挪窗口
3. 设置页消息简化：拖文字滑块只发 `textSize`，外壳收到后自动记为解锁；点锁（锁着时）= 发当前人物大小作 `textSize`（解锁、字不变）；点锁（解开时）= 发 `textLinked=true`
